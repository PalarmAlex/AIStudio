# AGENTS.md — Правила проекта AIStudio

AIStudio — клиентский UI-слой (WPF) над ядром `isida`. Находится в `D:\Программы\ISIDA\Programms\app\AIStudio`. Правила собраны из `.cursor/rules/*.mdc` и практики проекта.

## Общие принципы

- **Простота прежде всего.** Не усложняйте там, где не нужно.
- **Факты важнее предположений.** Проверяйте факты по коду и логам, прежде чем делать вывод.
- **Действуйте, а не только описывайте.** При изменении кода реально правьте файлы, а не предлагайте диффы.
- **Ответы пользователю — на русском.** Комментарии в коде — на русском (как в существующем коде). UX-текст — русский, явный, без внутреннего жаргона.

## Протокол отладки — `DEBUG_CASEBOOK_1.md` …

Рядом лежит **протокол разобранных ошибок** проекта: симптом → гипотезы → корень → исправление → эвристики. При росте файла заводите следующую часть (`_2`, `_3`, …).

- **Прежде чем искать причину бага — прочитайте `DEBUG_CASEBOOK_*.md`** (разделы «Эвристики» и случаи). Если симптом похож — начинайте с уже известного корня, тупиковые ветки не повторять.
- **После каждого исправленного бага — добавьте случай** по шаблону из того же файла (включая опровергнутые гипотезы) и, если правка обобщается, новую эвристику. Это обязательная часть работы.

## Компиляция

Проект — **.NET Framework 4.8 + WPF**, файл `AIStudio.csproj`, решение `AIStudio.sln`. Предпочтителен **MSBuild из Visual Studio**, а не `dotnet msbuild` (последний часто падает на `GenerateResource`).

```powershell
& "${env:ProgramFiles}\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" 
  "D:\Программы\ISIDA\Programms\app\AIStudio\AIStudio.csproj" 
  /t:Build /p:Configuration=Debug /v:minimal
```

- Если Community нет — замените на `Professional` или `Enterprise`; при сомнении найдите `MSBuild.exe` под `Program Files\Microsoft Visual Studio\2022\`.
- **Связь с `isida`:** AIStudio ссылается на `..\..\isida\bin\$(Configuration)\isida.dll`. Если меняли `isida` — **сначала** соберите `isida` Debug, **затем** AIStudio Debug.
- **Завершение задачи допустимо только** если сборка Debug прошла без ошибок (предупреждения — по ситуации, новые не игнорировать без причины).

## Язык и стандарты C#

- **Версия C# — 7.3** (`<LangVersion>7.3</LangVersion>`). Не использовать синтаксис C# 8.0+: `is not`, `and`/`or` в паттернах, `switch`-выражения, `record`, `init`, target-typed `new`, `with`, дефолтные члены интерфейсов. Предпочитать классические проверки (`if (!(x is int y))`, явные `out`, блочные `ConvertBack`).
- **MVVM:** логика UI — в ViewModels, разметка/компоновка — в XAML, доменная логика остаётся в `isida`. Не дублировать ядро `isida` в AIStudio — потреблять сервисы через `IsidaContext`/существующие контексты и явную передачу зависимостей.
- **Команды:** везде использовать `AIStudio.ViewModels.RelayCommand` для `ICommand` во всех ViewModel и диалогах. При необходимости добавить `using System.Windows.Input` и `using AIStudio.ViewModels`. Не вводить другие реализации (`RoutedCommand`, `DelegateCommand`).
- **Конвертеры WPF:** прежде чем добавлять класс в `Converters/`, просмотреть существующие и привязки в XAML. По возможности переиспользовать/доработать существующий (через `ConverterParameter`, общий хелпер), а не вводить дубль с дублирующей логикой.
- **Подписки на таймеры/события:** если ViewModel подписывается — обязан безопасно отписываться (`IDisposable`, `Dispose`). `INotifyPropertyChanged`: поднимать только нужные свойства, без «шума».
- **Отзывчивость UI:** долгие операции не блокируют UI-поток; обновление UI — через `Dispatcher`.
- **Не добавлять** логику инициализации движка ISIDA в AIStudio — AIStudio только конфигурирует/использует API движка.

## XAML — безопасность

- Никогда не задавать `Style` и `Control.Style`/`TextBlock.Style` одновременно на одном элементе.
- Перед `StaticResource` убедиться, что ключ есть в текущей области или слитых словарях.
- Триггеры — минимальные и детерминированные; не «воевать» за `Visibility`/`Opacity`.
- Для опциональных панелей привязывать `Visibility` к явному флагу VM (`BoolToVisibilityConverter`), а не к визуальным хакам. Привязки — One-Way, если не нужна Two-Way.
- Не менять анимации карточек стилей без явной просьбы; текстовые блоки — без лишней пульсации.
- После правки XAML сначала проверять ошибки компиляции изменённого View — каскадные ошибки ресурсов часто идут от одного битого узла.

### ComboBox: не задавать `ItemTemplate` в XAML

Задание `ItemsControl.ItemTemplate` у `ComboBox` в XAML приводит к **XamlParseException** при запуске (конфликт стилей, в т.ч. локального `BasedOn` и глобальных стилей из `Styles/ComboBoxStiles.xaml`).

Вместо `ItemTemplate`:
- нужен номер/ключ в списке и при выборе → `DisplayMemberPath` и `SelectedValuePath` по свойству элемента (например `StageNumber`);
- нужна доп. информация по пункту при наведении → **не** `ItemTemplate`, а `ItemContainerStyle` со `Setter Property="ToolTip" Value="{Binding Description}"/>`; подсказка по выбранному значению — `ToolTip="{Binding SelectedItemDescription}"` на самом `ComboBox` (свойство из ViewModel).

## Форматирование (пустые строки)

Не разделять **каждую** строку пустой. Пустые строки — только для логического разделения блоков.

**XAML — без пустой между:** одноимёнными дочерними элементами одного родителя (`RowDefinition`, `Setter`, колонки `DataGrid`); строками продолжения одного элемента; открывающим тегом блока и его первым дочерним элементом. **С одной пустой:** между секциями после закрывающего тега (`</Grid.RowDefinitions>` → следующий sibling); блоками `Resources`/`Style` и следующим логическим блоком; корневым элементом и первым дочерним блоком разметки.

**C# — без пустой между:** строками `using` одной группы; строками внутри метода/инициализатора/`get`/`set`/тела `if`/`for`/`foreach`; строками `///` одного комментария; XML-комментарием и следующим членом класса. **С одной пустой:** между блоком `using` и `namespace`; методами и свойствами класса (после `}` предыдущего); логическими секциями внутри класса (поля → конструктор → команды → методы).

## XML-комментарии

- Публичные/внутренние типы, методы, свойства, поля — с `///` (`<summary>`, при необходимости `<param>`, `<returns>`). Писать сразу при создании/изменении кода.

## Данные и окружение

- Данные и настройки — под `%ProgramData%\…` (как у Velum/ISIDA). Параметры — через конфигурацию проекта (`AppConfig.cs`).
- Пульсация/таймеры среды — через `GlobalTimer` (`isida`); подписки на `GlobalTimer.PulsationStateChanged` снимать в `Dispose`.
- Логи прогона сценариев/рефлексов — в `%ProgramData%\VELUM\Logs\` (`AgentLogs.jsonl`, колонки «Состояние», «Стиль», «Триггер», «Б/У рефлекс»). При разборе порядка фаз смотреть временные метки записей.
